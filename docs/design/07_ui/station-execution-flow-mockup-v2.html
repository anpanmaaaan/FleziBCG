MES Operator Cockpit · v2 (PO-SA)

Station Execution Flow Mockup v2

This version fixes the blockers identified in the v1 mockup review: Mode A becomes a 3-row single card with no Shell, no 5-step wizard, plus empty-state and error-banner coverage; Quality Measurement drops the "pass preview"; Quality Hold splits into separate Operator and QA routes; End Session gains a close-confirm dialog owned by CloseSessionPanel.

Backend is the source of truthAction visibility, hold state, closure, allowed_actions are all backend-derived. FE never computes command legality.
One primary action per modeEach screen state surfaces exactly one primary CTA. Secondary actions do not compete for attention.
Token-compliant hit areaPrimary CTA ≥ 56px, secondary ≥ 48px, gap ≥ 12px, KPI value ≥ 48px.
Color + icon + textState never relies on color alone. Pills carry a dot plus a text label. Color-blind operators can still read every state.

i18n Notes (en + ja registries)

All operator-visible copy in this mockup is English placeholder text only. The production app resolves every string through the i18n hook against two registries that must stay in lock-step: frontend/src/app/i18n/registry/en.ts and frontend/src/app/i18n/registry/ja.ts. The parity lint scripts/check_i18n_registry_parity.mjs enforces the key set match.

Key namespace pattern (additive — do not rename existing keys in any implementation slice):

  • stationSession.row.session.* — Session row title, subtext variants, actions
  • stationSession.row.operator.* — Operator row title, subtext variants, action
  • stationSession.row.equipment.* — Equipment row title, subtext variants, action
  • stationSession.row.status.* — Pill labels (Open / Identified / Bound / Not yet / Optional / Not confirmed)
  • stationSession.cta.enterQueue — Primary CTA label
  • stationSession.cta.helper.* — Helper text variants for disabled CTA
  • stationSession.empty.missingStation.* — Empty-state title / message / CTA
  • stationSession.close.* — Close-confirm dialog title / body / actions
  • stationExecution.hero.* — Cockpit hero state labels
  • stationExecution.action.* — Cockpit action labels (Report quantity, Pause, Resume, Start / End downtime, Complete)
  • stationExecution.interrupted.* — Interrupted-mode banners (paused, downtime)
  • stationExecution.downtime.dialog.* — Start-downtime dialog labels
  • quality.measurement.* — Measurement entry labels and spec reference
  • quality.hold.operator.* — Operator hold view
  • quality.hold.qa.* — QA resolution view
  • supervisor.timeline.* — Supervisor read-only timeline

Rules: never hardcode operator-visible strings in JSX; never delete existing keys in this feature (orphan cleanup is a separate hygiene slice); always add the same key to both en.ts and ja.ts in the same commit; numeric formatting and date formatting must use locale-aware helpers (not raw template literals).

Implementation notes for the coding agent

Scope intent: visual direction pack, not production code. Map onto existing components — StationWorkflowShell, OpenSessionPanel, IdentifyOperatorPanel, BindEquipmentPanel, CloseSessionPanel for Mode A, plus ExecutionStateHero, AllowedActionZone, QuantitySummaryPanel for Mode B.

Hard requirements:

  • Mode A MUST NOT use StationWorkflowShell, MUST NOT use StationEntryPanel, MUST NOT show a 5-step wizard (D-01 / D-02).
  • Mode A has exactly one top-level primary CTA "Enter queue"; helper text names the missing prerequisite (D-05, IR-06). Variable name MUST be canNavigateToQueueByVisibleSetupState.
  • Error display: one top banner, no toast on failure for command-guard codes (D-04, IR-05).
  • Empty state when !stationId: one amber notice, no Shell, no rows (D-08).
  • Close-session confirm dialog is OWNED by CloseSessionPanel (IR-01).
  • Cockpit (Mode B): action visibility comes from allowed_actions; no STX label, no generic partial banner.
  • Quality Measurement: do not render any "pass preview" / "no hold will be opened" copy. After submit, the backend returns quality_result.
  • Quality Hold: separate Operator and QA views (different routes / authorization), never side-by-side.
  • Touch targets: primary ≥ 56px, secondary ≥ 48px, gap ≥ 12px, KPI value ≥ 48px.
  • Pill states: dot + label (color + text), never color alone.
  • Focus-visible ring on every interactive element.
  • aria-hidden="true" on decorative symbols (●, ○, dot, step number).
  • All operator-visible strings go through i18n (en + ja parity). See "i18n Notes" section above.

Suggested slice order:

  1. FE-SE-MODEA-SIMPLIFY-09 — Setup 3-row card, empty state, error banner, close-confirm dialog ownership.
  2. FE-SE-COCKPIT-HERO-10 — Mode B hero, allowed_actions zone (active state).
  3. FE-SE-INTERRUPTED-MODE-11 — Cockpit paused and downtime-open visual modes.
  4. FE-SE-START-DOWNTIME-DIALOG-12 — Start-downtime modal with backend reason list.
  5. FE-SE-QUALITY-MEASURE-13 — Quality entry spec-reference panel; remove the pass preview.
  6. FE-SE-QUALITY-HOLD-SPLIT-14 — Operator hold view plus QA disposition route (separate).
  7. FE-SE-SUPERVISOR-TIMELINE-15 — Supervisor timeline read-only.

Caveats: reason codes, disposition list, spec ranges, downtime reasons are all backend-derived master data — do not hardcode in FE.
