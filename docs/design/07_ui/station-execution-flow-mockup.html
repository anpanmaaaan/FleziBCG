Station Execution Completed Flow

This screen pack shows the full pilot path from station entry to session end. It is intentionally discrete-first while preserving generic execution language for future batch/process expansion.

Backend truthAllowed actions, holds, session ownership, and status are displayed, not invented client-side.
One primary actionEach state has one main operator action in the visible frame.
No debug shellSTX labels and workflow diagnostics stay out of normal execution mode.
Quality gatesMeasurement and hold states block completion when backend requires it.
Supervisor visibilityTimeline and current state are clear without taking over operator flow.

Implementation Notes For Coding Agent

Scope intent: use this as a visual direction pack, not production code. Translate into existing React/Tailwind components and backend-driven state.

Hard requirements: backend-derived allowed actions, one primary action per state, no STX/debug shell in Mode B, no generic partial banner when screenStatus says connected, screenshots with negative assertions for removed clutter.

Suggested slices: first implement Mode B cockpit integration, then station setup wizard, then quality/hold states, then supervisor timeline. Keep each slice independently screenshot-verified.
